Как это работает
  • Строка заголовков ищется автоматически (по столбцу Summary или Название).
  • Понимаются столбцы: Project/Проект, Summary/Название, Issue Type/Тип, Priority/Приоритет, Status/Статус, Assignee/Исполнитель, Reporter/Автор, Team/Команда, Customer/Заказчик, Sprint/Спринт, Created/Создана, Updated/Обновлена, Description/Описание. Остальные пропускаются.
  • Проекты, команды, заказчики, статусы и спринты создаются автоматически, если таких ещё нет.
  • Исполнитель и автор ищутся по имени среди пользователей системы; незнакомые имена остаются пустыми (пользователи не создаются).
  • Типы Jira: Task → Task, Bug → Bug, Story → Feature, Sub-task → Task, Epic → Epic. Неизвестный тип станет Task.
  • Тип Idea (или Идея) импортируется как идея в раздел «Идеи», а не как задача. У идеи берутся Название, Описание, Приоритет, Исполнитель, Автор, Проект, Команда, Заказчик, Компонент. Статус берётся из справочника статусов идей (создаётся при необходимости). Спринт, Parent Link и иерархия к идеям не применяются.
  • Parent Link — полное название (Summary) родительской задачи. Родитель ищется сначала среди задач этого же файла, затем среди уже существующих в базе (по точному совпадению названия). Иерархия соблюдается: Feature → под Epic, Task/Bug → под Feature. Если родитель не найден или не подходит по иерархии — задача создастся, но без связи, и это попадёт в список ошибок перед импортом.
  • Строки с пустым названием не импортируются (задачи без названия не бывает) и тоже попадают в список ошибок.

Экспортированный из трекера файл можно импортировать обратно — столбцы совместимы.
